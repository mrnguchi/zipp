## Mandatory implementation rules

- Use feature-owned Nest modules, strict TypeScript from the first commit, constructor injection, explicit public contracts, and thin transport handlers.
- Keep domain logic independent of Nest, Prisma, Redis, and network providers. Follow the dependency direction and folder conventions in the architecture.
- Explain non-obvious business rules, concurrency choices, invariants, and recovery behavior in comments. Do not narrate obvious syntax or create empty abstractions/files for appearances.
- Use PostgreSQL as the source of truth, Prisma for persistence, exact XAF money, transactional booking/settlement, persistent idempotency, and a transactional outbox.
- Protect every transport with runtime validation, account/role/ownership policies, bounded input, shared rate limiting, and safe logging. Use cryptographic OTP/PIN generation.
- Run the API, worker, database, and Redis services in separate containers. Use the shared image and CI/CD contracts in the infrastructure document.
- Never make network calls inside database transactions, trust client prices/payment success, use Redis locks as sole financial correctness protection, or rely on process-local state for cross-instance decisions.
- Write meaningful behavior, authorization, integration, race, and recovery tests for the feature. Document-only edits require document checks, not runtime tests.
- Implement performance budgets and failure behavior. Do not claim 1,000-user capacity without a reproducible load report.
- Treat tracking, signaling and media as separate paths. Authorize location/call participants, handle stale/reconnected clients, and verify native background behavior; never send continuous audio through Nest handlers or queues. User/RPS capacity does not establish concurrent-call capacity.
- Keep secrets out of source, images, logs, CI artifacts, and mobile public variables. Mock adapters must fail closed outside explicit dev/test configuration.
- Track reviewed schema migrations and dependency lockfiles. Identify the target database before migrations/seeds; never reset an unidentified or production database.
