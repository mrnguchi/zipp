## Local preparation and compilation

From `mobile/`, `npm run voice:android:prepare` creates an Android native tree only if none exists. It refuses an existing tree and explicitly passes `--no-clean` (required by installed Expo 58 CLI), installs no packages, launches no emulator/phone and preserves npm convenience scripts. Existing native modifications require deliberate review before refreshing config. This pass initially created a new ignored `mobile/android` tree. Earlier refresh invocations omitted `--no-clean` and Expo recreated that generated tree, discarding its app build/task cache. This was an implementation mistake; the helper now explicitly prevents that default behavior. Future reviewed refreshes must also explicitly use `--no-clean`; absence of `--clean` is insufficient on this CLI.

The compile helper is `mobile/scripts/build-voice-android.ps1`; supply installed JDK and Android SDK directories if defaults do not match your machine. It checks that the voice microphone configuration reached the generated manifest, uses process-only environment variables and restores them afterward. It assembles ARM64 debug only, one Gradle worker, Kotlin in-process, no daemon, excluding test and lint tasks. This is not a limit on all Ninja compiler subprocesses. It does not install/run an APK, start adb/emulator, accept new SDK licenses, change global environment or publish anything. Native compile caches/downloads are needed; Expo metadata lookups stay offline. The helper's PowerShell syntax was parsed; the equivalent Gradle command was executed directly for this evidence.

From the workspace root, prepare once with `npm --prefix mobile run voice:android:prepare` when the Android tree is absent. Compile an already prepared tree with `& .\mobile\scripts\build-voice-android.ps1` under your approved local PowerShell script policy. Optional helper parameters are `-JavaDirectory` and `-AndroidSdkDirectory`; do not change backend `.env` for this mobile build. The expected output is `mobile/android/app/build/outputs/apk/debug/app-debug.apk`; its presence/result must be confirmed after Gradle succeeds. ARM64 packaging is not an x86 emulator build or an iOS build. This pass does not install that output on a device.
