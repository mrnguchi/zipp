# ADR 0007: M4 driver eligibility, private uploads and versioned quotes

Date: 2026-11-12. Status: backend source and local development migration present; tests remain unrun by user direction. See [M4 evidence](../M4_VERIFICATION.md).

## Scope and decisions

Implement feature-owned drivers and pricing modules using existing Node 24.18.0, Nest 12.3.3, Prisma 7.10.1/PostgreSQL 18.6 and Zod 4.6.7. Install no new package/service. Identity owns role changes through its facade. Driver applications own versioned vehicle/documents, independent ADMIN review, suspension and server-issued location epochs. Pricing owns service areas, immutable policy versions and expiring server-owned quotes.

The user authorizes sample fares until later updates. Use deterministic, clearly identified development fixtures, not newly random fares per request. Development v1: Everyday base 500/per km 200/per minute 30/minimum 1,000 XAF; Comfort 700/280/42/minimum 1,400; Premium 1,000/400/60/minimum 2,000; Standard delivery 400/150/20/minimum 800; Express 600/225/30/minimum 1,200. Initial illustrative night multiplier 12,500 basis points for 22:00-06:00 Africa/Douala, commission 1,000 bps and pre-pickup cancellation fee 500 XAF. These are not approved commercial/provider/legal rates. All rates/version/service-area terms are snapshotted in quotes and require later product review. No client fare/distance is authoritative.

Canonical service classes match mobile labels EVERYDAY/COMFORT/PREMIUM; PRD Classic maps to EVERYDAY, Comfort Plus to PREMIUM, Comfort to COMFORT. Delivery classes DELIVERY_STANDARD/DELIVERY_EXPRESS remain a perspective within Delivery, not a separate Logistics product. Completion PIN is required later; no start PIN added in M4. Sending and receiving contacts remain explicit M6 fields; private driver documents do not become public contacts. Cancellation beyond pickup requires later lifecycle policy; the sample fee is not automatically charged here.

Local routing is a fixed fixture adapter for one labelled development route, never a geometric straight-line fare fallback. It accepts only the fixture endpoint pair (and reverse), returns fictional 5,000 meters/900 seconds and rejects other routes. Service-area endpoint validation alone does not establish that every intermediate road point lies in the area. Actual road providers, route geometry/service-area validation and commercial rules require M8 integration before production. Quotes expire after two minutes, belong to their actor, carry route/policy versions and can be consumed once by a future booking in the same transaction as the hold. Repricing creates a new quote; consumption rechecks current active policy and service area. Disable fixture routing/quotes in production; local enablement is explicit.

Private document uploads use an opt-in local filesystem adapter behind a storage port, with a dedicated persistent local volume, UUID server keys, create-only writes, private directory/file permissions and digest/length/type checks. No public file server or client paths/URLs. Bounded raw binary upload avoids a new multipart package; authenticated handlers read at most 3 MiB, with a 10s receive deadline and per-process concurrency admission for memory only. Global JSON remains 16 KiB. Files are downloaded as attachments with no-store/nosniff only by owner or recent-MFA ADMIN, with audit. File magic does not prove safety: explicit human review is required; malware scanning/real private object storage and shared multi-host storage are pre-production gates. Production rejects the local adapter. Orphans after storage/DB failures remain private for reviewed reconciliation; never delete an unidentified path automatically.

Application states DRAFT/SUBMITTED/APPROVED/REJECTED/SUSPENDED. Changes occur only in editable states; resubmission increments revision, invalidates prior decisions and requires all required documents/vehicle. Approval checks immutable content digests, current revision, unexpired documents and assigns server-reviewed class eligibility. Review reasons/history persist. Suspended/expired/unapproved drivers cannot publish useful presence; public role preference does not grant DRIVER. Repeated commands must not silently overwrite different input or duplicate review effects.

Location sessions are PostgreSQL-backed bounded latest snapshots for M4 HTTP eligibility, not a full tracking feed. Keep only latest coordinates, no route/audio history. Server creates an epoch per online transition, fixed maximum 12h, monotonic sequence, captured/received times, accuracy <=100m, age <=15s, future clock skew <=5s, updates <=1/3s. Derive actor from session. Offline/suspension/new epoch invalidates the old epoch. Eligibility requires accepted fresh position <=15s plus current approval/documents/session; 30s without telemetry is unavailable. Device coordinates are observations, not GPS spoof-proof evidence. Native background upload, Redis geo fanout, participant subscriptions and dispatch assignment are M5/M7 gates; no active-job index exists yet, so availability changes must be integrated with assignment locks before bookings are enabled.
