# ADR 0011: M7.1 participant live stream and REST recovery

Date: 2026-11-20. Status: implementation; runtime/security/load/native verification pending on command. This starts M7; it does not complete chat, push, calling or operations.

## Scope and dependency decision

Add a feature-owned `realtime` module as an opt-in API-only Socket.IO transport. Use Socket.IO 4.8.4 and matching client 4.8.4 with existing Nest 12.3.3 lifecycle/HTTP adapter injection, Node 24.18.0, strict TypeScript 5.9.3 and existing Redis/PostgreSQL adapters. No Nest gateway decorator package is needed: a thin Socket.IO server provider attaches to the existing HTTP server during application bootstrap. No new port/container/service, schema/table/migration or worker identity key is required. Do not install the Nest Socket.IO adapter solely for wiring that the existing HTTP adapter already provides.

Before installation, reviewed current [Nest gateways](https://docs.nestjs.com/websockets/gateways), [adapter contracts](https://docs.nestjs.com/websockets/adapter), [Socket.IO server options](https://socket.io/docs/v4/server-options/), [server API](https://socket.io/docs/v4/server-api/), [client options](https://socket.io/docs/v4/client-options/), [delivery guarantees](https://socket.io/docs/v4/delivery-guarantees/) and [Redis Lua atomicity](https://redis.io/docs/latest/develop/programmability/eval-intro/). Exact npm manifests confirm server 4.8.4 Node >=10.2 and client 4.8.4 Node >=10; Nest's 12.3.3 optional Socket.IO platform adapter itself selects server 4.8.4. The public release-tag URL did not resolve, so installed version-matched package source/types/manifests plus official v4 docs are compatibility evidence, not a fabricated release note. No major upgrade or force/legacy-peer override. Socket client is JavaScript-only; physical mobile websocket/reconnect/proxy behavior still needs execution.

## Transport and authorization

Transport path `/api/v1/live/socket.io`, namespace `/`, websocket-only, no long polling or sticky-routing assumption. No connection-state-recovery shortcut or skipped middleware. Access credentials go in strict Socket.IO auth `{schemaVersion:1,accessToken,jobType:'RIDE'|'DELIVERY',jobId,afterVersion}`. No token in query/URL; reject unexpected query/auth fields, binary/custom client events and unsupported namespaces. One job per connection, immutable until reconnect. Public delivery tracking capabilities cannot join this private stream; support/finance/admin roles alone do not confer participant access.

Reauthenticate the original access token and reauthorize current session/account/ownership on every projection cycle. Owning ride/delivery modules expose focused public `liveSnapshot(actor,id)` facades; transport never imports their repositories. Read status/version/terminal and authorized latest position under one feature transaction with the existing sorted participant -> driver -> job lock order. Emit only state/custody/version, fresh/stale latest position and server timestamp, never contact, price, photo, code, token, wallet or private location epoch. Terminal update removes location and closes the connection. Revocation/expiry/dependency failure closes the connection; no cached permission continues a feed. Revocation latency is bounded by the next cycle plus an in-flight bounded transaction, not claimed instantaneous across replicas.

## Initial simple multi-instance policy

This first slice uses authoritative pull projections, one at a time per socket every three seconds, with at most four projections in flight/API process and 50 admitted sockets/process. It emits complete minimal snapshots, not financial mutations or transient-only event history. Existing persisted versioned ride/delivery events and REST snapshots remain the reconnect source of truth. `afterVersion` marks whether the client needs a resync; it is never accepted as authoritative state. Slow/unwritable sockets are disconnected instead of accumulating an unbounded output buffer. Initial and reconnect snapshots always cause a REST refresh; subsequent versions cause bounded/coalesced refreshes. GPS is latest-value telemetry, not a ledger/outbox row per point.

Use the existing queue Redis (`noeviction`) for short, expiring connection leases: max two/account, 20/IP and 500 global across replicas, atomically acquired/renewed with Redis server time and UUID membership. Renewable 20-second leases never resurrect an expired identity and fail closed on Redis loss; crashed processes free capacity by expiry. Cache/rate-limit Redis additionally enforces handshake/IP and actor budgets. Process-local maps hold only connection handles/timers/admission memory; cross-instance correctness/limits use PostgreSQL and shared leases. Do not interpret socket loss or lease expiry as permission to release any job, funds, custody or call slot.

No room broadcasts or Redis pub/sub fanout are used in this slice, so one instance never needs another's socket map. Each admitted stream reads current authoritative state regardless of the API instance that performed a mutation. A Redis room adapter/outbox relay is deferred until a measured fanout slice needs it; adding a broadcast later without an adapter and current per-recipient authorization is prohibited. This deliberate initial three-second polling stream does not claim to meet the target propagation p95 <=2s or 1,000-user acceptance; the global ceiling is initial load shedding. Measure and replace/multiplex the read path before raising caps or claiming scale. Documented target budgets remain unchanged.

## Enablement, client and failure behavior

Raw Engine.IO clients and pending upgrades share a 64/process ceiling. Reserve before asynchronous Redis ingress checks, and expire pending reservations after five seconds; also bound namespace authentication to five seconds. Mobile checks frame freshness every five seconds and reconnects after more than 12 seconds without a valid frame. A protocol heartbeat alone does not establish a healthy authorized projection.

`REALTIME_ENABLED=false` by default; when false no Socket.IO listener exists. Enabled local mode requires identity and explicit origin policy. Browser origins must match `REALTIME_ALLOWED_ORIGINS` exactly; native no-Origin connections are permitted only when `REALTIME_ALLOW_NATIVE=true` is explicit. No wildcard, userinfo/path/query origin or forwarded-IP trust. Reject production enablement until this transport's security/load/native acceptance is recorded. Edge pre-upgrade/TLS/DDoS limits remain hosting work.

Mobile uses the existing feature/session contracts and the Zipp frontend skill. `EXPO_PUBLIC_REALTIME_ENABLED=false` default. When enabled, foreground delivery subscribers connect with a current access token, refresh/coalesce authorized REST state, apply only matching nondecreasing aggregate versions and clear stale position on disconnection. Keep periodic REST recovery, reduce its cadence while live traffic is fresh, close on background/navigation/account changes, and reconnect with bounded exponential backoff/jitter/current token. Do not persist a socket token or put it into the map WebView. Ride transport has the same backend contract; its existing demo screen is not silently converted into a server booking flow.

Write behavior/authorization/lease/failure/reconnect test source without execution. No real SMS/push/media/provider, hosting, microphone/background permission, native calling library or new paid infrastructure is enabled. Calling requires a separate provider/self-hosted decision and native/media evidence; it remains pending/disabled. Chat, tickets, notification outbox/devices, staff permissions/reports and audits remain later M7 slices. Update M7 status honestly with actual allowed build/static evidence.
