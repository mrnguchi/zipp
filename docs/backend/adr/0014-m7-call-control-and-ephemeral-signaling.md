# ADR 0014: M7.4 local call control and ephemeral signaling

Date: 2026-11-21. Status: implementation; migration, runtime/race/security/native/media verification pending on command. This is a calling foundation, not completed internet audio or M7 acceptance.

## Provider and compatibility decision

Implement `calling` as a default-disabled local control-plane feature. Reuse Node 24.18.0, Nest 12.3.3, Prisma 7.10.1, PostgreSQL 18, ioredis 5.8.2, Redis 8.2.3 and Zod 4.6.7; no install/upgrade/new service. The only mode is `local_control`: no audio, TURN/media credentials, media-connected endpoint, telephone fallback, VoIP push or native SDK. A managed provider versus self-hosted TURN/direct or relay-only media remains a separate pre-enablement decision; this slice deliberately does not select/provision a paid host or media service. It cannot be enabled in production.

Reviewed official [W3C WebRTC recommendation](https://www.w3.org/TR/2025/REC-webrtc-20250313/), [Redis Lua](https://redis.io/docs/latest/develop/programmability/eval-intro/), [PostgreSQL 18 locks](https://www.postgresql.org/docs/18/explicit-locking.html) and [Node 24.18 crypto](https://nodejs.org/download/release/v24.18.0/docs/api/crypto.html) on 2026-11-21. Reuse installed Prisma 7 generated types/unit-of-work rather than newer-major web examples (ADR 0012); installed ioredis types plus existing bounded Lua adapter establish selected-version command compatibility. No native compatibility claim from backend compilation. Mobile manifest currently declares Expo ~58.0.19/RN 0.88.0/React 19.3.0; no calling library or native spike/build was added or verified.

## Eligibility, identity and lock order

Calls are one-to-one between a current assigned ride customer/driver, or delivery courier and one current booker/verified bound sender/recipient. No sender-recipient direct calling, self call, arbitrary directory, unverified phone capability or role-based staff override. Owning ride/delivery facades authorize the actor, lock sorted current participant IDs plus the requested peer, then the job and aggregate, and return a minimal eligibility boolean. Require active peer account. Terminal/unassigned/wrong-pair jobs cannot initiate/answer/negotiate calls. Assignment/status are rechecked for every signal command/read and acceptance.

Reuse Notifications' client-owned LOCAL installation proof/session/generation through a narrow public facade; no token/provider endpoint is exposed. Caller binds one current device/session/generation at create. The first valid callee device atomically claims ACCEPT; other devices cannot negotiate or end that accepted leg. A signed-in original participant may read minimal call-control history from another device; signals require the exact claimed session/device/generation/proof. END authorizes original participant and claimed leg without requiring continued job eligibility, allowing safe cleanup after reassignment/termination. No call action changes a ride, assignment, parcel custody or money hold.

Active commands lock identity before job (where needed), device and call; the reaper locks original identities then call and reads device state. All registration/session changes serialize on user locks. Never lock call then acquire a new user/job lock. A PostgreSQL unique slot per account protects at most one active call across jobs/devices, and a unique side per call ensures one caller/callee slot. Admission is capped at 100 local control sessions under a transaction-scoped PostgreSQL advisory lock; count/cap/slots are not Redis/process-local correctness. Caller quota 5/min and persisted symmetric pair cooldown 30s, in addition to shared REST and action/signal bounds. These are development budgets, not measured audio capacity or abuse/block-list completion.

## Durable state and recovery

Four tables: `call_sessions`, `active_call_participants`, `call_commands`, `call_events` (58 total application tables defined). Additive migration is source only; last identified applied local evidence remains 45/base `m6`. Optional marker `calling=m7_4` supplements existing communications/notifications markers when enabled. No migration/reset/seed or live service startup is performed here.

States implemented: `RINGING -> CONNECTING` after atomic acceptance; terminal `REJECTED`, `MISSED`, `FAILED`, `ENDED`. There is deliberately no CONNECTED state/client command because no media path proves bidirectional audio. Ring expires after 30s; local CONNECTING expires after 30s and becomes FAILED, never a fabricated connected call. Terminal state releases only call slots and cannot resurrect through delayed answer/signaling. Metadata event/outbox intents record version/type/actor/timestamp/reason only; no SDP/ICE/audio/credential payload. They are not a verified ring publisher or native wakeup mechanism.

Create/accept/reject/end require UUID Idempotency-Key scoped actor/action/key, HMAC canonical input fingerprints and immutable call/version/status receipts. Fresh identity/private participant checks precede replay; same input recovers its original receipt, changed input conflicts, keys are not automatically expired/reused. GET supplies current state. Device proof is write-only and fingerprinted, never copied into history. A new terminal END is harmless; replay cannot re-claim an active slot. Timeout cleanup is committed before returning an expired-command conflict, rather than rolled back with that HTTP error.

API get/active snapshots are minimal metadata for original participants, with no phone, push proof/token or signaling. Current job eligibility gates negotiation, not access to one's prior minimal call metadata. No staff history override. A default-disabled reaper in the existing worker checks up to 20 nonterminal calls every two seconds using persisted check order; it handles deadlines and inactive/revoked/expired claimed accounts/sessions/devices. It needs no JWT/signaling encryption keys. Job completion/reassignment immediately blocks further signal authorization; absent further requests, the finite local deadline bounds remaining reservations. No socket-disconnect auto-end or job release. Reaper scheduling and multi-device races remain unverified until tests are commanded.

## Signaling transport and privacy

Local diagnostic signaling uses bounded REST send/read commands, not the M7.1 read-only socket and not a second signaling system alongside a provider SDK. Future media selection must replace/adapt this transport explicitly. Each sender has at most 64 packets in one accepted epoch; caller first sends OFFER, callee first ANSWER, subsequent packets are ICE. SDP <=8 KiB, ICE candidate <=1 KiB, no arbitrary event/recipient/room. Sequence and UUID message identity are idempotent with changed-payload conflict. Callee losing devices and refreshed-but-different auth sessions cannot receive another endpoint's SDP/ICE.

Raw signaling is never durable PostgreSQL/outbox/queue/history/log data. AES-256-GCM encrypts ephemeral cache-Redis envelopes with device-bound authorization metadata; HKDF separates cipher/fingerprint keys from dedicated API-only `CALL_SIGNAL_KEY`. AAD binds call/epoch/sender/sequence/message ID. Atomic Lua enforces per-direction contiguous bounded sequences, fingerprint replay and deadline, with absolute expiry no later than the CONNECTING deadline (<=60s hard buffer bound). Redis loss/eviction is missing negotiation state, not continued delivery: nonzero cursor/sequence against missing state returns resync-required. Do not reset counters silently; end/recreate a call if recovery cannot reconstruct negotiation.

Each send/read first authorizes in a short database transaction, performs Redis I/O after commit, then reauthorizes exact call version/epoch/device before returning. No network/cache call is made inside a DB transaction. Terminal cleanup relies on finite encrypted-key expiry and fresh read authorization; explicit Redis deletion is not currently scheduled. No cache I/O occurs during metadata closure. Reads return at most 32 packets, cursor and resync flag. Proof remains in POST body, never query/URL. Shared send/read quotas and 16 KiB HTTP bodies bound work; malformed/private adapter errors return safe envelopes. Encrypted Redis data still requires private Redis/auth/TLS and key management; no E2E audio-encryption claim.

## Flags, open gates and delivery

`CALLING_ENABLED=false`, `CALLING_ADAPTER=local_control`, worker-only `CALLING_REAPER_ENABLED=false`. Enabled API requires identity/notifications enabled and separate 32-byte hex CALL_SIGNAL_KEY; enabled worker reaper requires notification storage/eligibility configuration but no API signing or signaling key. No flags or ignored env values are changed. Runtime rejects production/unsupported adapters; capabilities explicitly report audio/native incoming call/TURN credentials unavailable. No recording, microphone permission or telephone disclosure.

Write policy, authorization/device-claim, replay/race/timeout/recovery/Redis-encryption/sequence and HTTP test source without execution. Allow offline Prisma generation/validation, source/test-source compilation, build/contracts, lint/format/boundaries/Compose/docs only. Actual SQL/queue/worker/Redis/provider/native/media tests remain pending. M7 calling is not complete until provider/privacy/retention decisions, native compatibility spike, incoming-call OS integration, short-lived media credentials/teardown, actual audio, real-device failure cases and independent media capacity gates are satisfied. Broader staff operations remain subsequent M7 work.
