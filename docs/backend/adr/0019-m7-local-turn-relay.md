## Deliberately local topology

Use a dedicated IPv4 bridge `172.30.240.0/29`, relay `172.30.240.2`. Prepare only against an explicitly selected RFC1918 address actually assigned to this machine; refuse collision with that bridge. Publish UDP/TCP 3478 on that address only. No wildcard/loopback/public host binding, host network, router/firewall mutation, default external-IP detection or extra relay media-port publishing.

This is a **single-relay, both-participants-relay-only** development topology. Relay candidates keep the container IP; coturn forwards between its own allocations. Deny all IPv4/IPv6 peer destinations except the exact container relay IP. No LAN host-IP exception, other private subnet, public peer or host-service target. Coturn 4.19.2 `good_peer_addr` checks loopback/internal deny defaults first, then explicit allowlist ahead of denylist; reviewed address code permits this RFC1918 IPv4 exception while retaining metadata/link-local restrictions. RFC 8656's forwarding model motivates using the server's own allocation endpoints; this topology's WebRTC/Docker behavior is an **inference requiring two-device acceptance**, not demonstrated media connectivity. Mobile must use the same relay with `iceTransportPolicy: relay`; mixed/direct/multiple-relay/IPv6/WAN scenarios are outside this profile. Do not expose or widen private peer access to fix a failing device check.

This topology reduces local exposed ports and prevents a general authenticated UDP proxy to the LAN. It does not establish internet call readiness, public-IP NAT/firewall correctness, TLS support, network isolation from a compromised container, peer-port filtering, account/call authorization inside TURN or production egress policy. Before public hosting, record/review a separate routable relay/TLS/certificate/UDP-media/firewall/abuse/observability design and qualify it. The local profile cannot be promoted as production infrastructure.

## Secrets, process and limits

Generate a fresh random 32-byte shared secret, stored as 64 lowercase hex ASCII characters, without printing it. Coturn and the future credential issuer use the **ASCII string** as the HMAC key, not hex-decoded bytes. Render the complete private configuration and a separate server-only key file under ignored `infra/calling/.local/`; refuse an existing directory/files, never overwrite/rotate active secrets. POSIX directory/file modes 0700/0600, non-root current UID/GID; Windows disables inherited ACLs and grants current-user access before any secret write. Abort on permission setup failure. Compose file secrets are bind mounts, not an encrypted vault; match POSIX host ownership instead of relying on ignored file-secret UID/GID/mode remapping. Docker administrators/current OS account remain trusted. No secret env/CLI values, Docker config output, mobile variables or log captures.

Bypass the image shell entrypoint/default public-IP lookup; execute `/usr/bin/turnserver` with only the private config path. Read-only root, bounded private tmpfs, non-root UID/GID, no-new-privileges, all capabilities dropped except NET_BIND_SERVICE, CPU/memory/PID/file limits, restart disabled. The single retained capability accommodates the selected upstream binary's declared file capability; verify the precise non-root/NNP runtime behavior before claiming it works. No NET_ADMIN/privileged/container socket. Native authentication/nonce, per-user/total allocation, port, bandwidth and thread bounds are configuration targets, not measured capacity or revocation guarantees. Keep logs discarded in this local privacy-first profile; safe operational metrics/diagnostics remain a later deployment gate.

UDP/TCP TURN control only on a trusted local network; TLS/DTLS listeners disabled and no certificate/client-validation bypass. WebRTC's eventual DTLS-SRTP media path is separate from TURN control TLS. No public or production plaintext deployment. Allocation refresh/short credential expiry does not immediately terminate an existing stream; later ongoing-call, credential renewal, teardown/revocation/reconnect work is mandatory before enablement. No change to diagnostic CONNECTING's current 30-second/one-negotiation policy.
