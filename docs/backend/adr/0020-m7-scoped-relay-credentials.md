# ADR 0020: private short-lived relay credentials and user-ended call policy

Date: 2026-11-24. Status: decision recorded before implementation; default-off issuer source and build/static checks present, tests/runtime/media acceptance pending. Actual evidence/limitations are in the [credential runbook](../M7_RELAY_CREDENTIALS.md). Continues [relay setup](../M7_TURN_RELAY.md) and [ADR 0019](0019-m7-local-turn-relay.md).

The user authorized backend-issued temporary TURN credentials and specified that participants should end their conversation themselves. **Healthy ongoing calls have no arbitrary conversation-duration cutoff; either claimed participant hangs up.** Credential expiry is not call duration. An eligible ongoing call will need automatic authorized renewal, endpoint liveness, bounded reconnect and explicit peer/microphone teardown. Revoked identities/devices, ended/reassigned jobs and abandoned connections still require safe cleanup. No job/custody/funds release on a call timeout. This preference supersedes any proposed fixed maximum healthy-call duration, not setup deadlines or authorization.

Keep this small slice limited to credential issuance for the existing accepted diagnostic CONNECTING state. Do not remove its 30-second setup expiry or invent CONNECTED/usable audio without a persisted media/liveness/reconnect contract and native implementation. That ongoing lifecycle is the next slice; its absence remains explicit in capabilities/runbook. No schema/migration or mobile change, and no claim that today's diagnostic call can already continue indefinitely. No tests, migrations, relay startup or media probes authorized by this request.

## Issuance contract

Add private POST `/api/v1/calling/calls/:id/relay-credentials` with strict claimed device/proof, expectedVersion and epoch:1 body. Default-off `CALL_RELAY_CREDENTIALS_ENABLED` on API only, requiring enabled local calling and notifications/identity. Worker must not receive relay secret configuration. Only the configured local RFC1918 TURN listener on port3478 with exact UDP/TCP URLs; no client-provided destination, TLS bypass, public host, broad URL or additional relay service.

Fresh current job, both identities/sessions/installations and exact requester claim are checked under existing identity/job/call locks. Reject RINGING/terminal/expired/changed-epoch/version/unclaimed requests; timeout cleanup must commit before returning conflict. Shared issuer quota six/minute/account plus global request quota; retries consume it. Mint only after the transaction ends, then reauthorize current state/version/epoch/device before release. No secret I/O or provider/network operation in a DB transaction. Returning a credential still has a finite response-race window; TURN is bearer auth, not a participant-aware authorization server.

Use coturn 4.19.2 TURN REST authentication: username `expiryUnixSeconds:opaqueScope`, credential Base64 HMAC-SHA1 over that exact ASCII username with the same server-only ASCII secret read by coturn. This SHA1 use is the provider protocol, not password storage or an arbitrary new signing algorithm. Derive opaqueScope using purpose-separated HMAC-SHA256 binding call, epoch, both session/device/generation claims and requesting side; no raw account/job/call/device identifiers in username. Use fixed expiry floor(acceptedAt/1000)+60 seconds for this diagnostic negotiation: retries recover the same temporary username/password, do not slide expiry or create unbounded per-user relay quotas, and do not change call state or create persistent key receipts. Authorization is always rechecked; an expiry cannot resurrect or reuse a terminal call. This can leave credentials valid briefly beyond a setup/end transition and cannot revoke existing allocations immediately.

No durable credential/key/proof/SDP/ICE logging, event, history, queue, database receipt or automatic financial key reuse. Response Cache-Control:no-store and strict private authentication; mobile future integration keeps credentials only in memory. Return expiry, serverTime, relay-only policy and explicit audioAvailable:false. No idempotency header: this endpoint is an authenticated ephemeral grant read, not a persisted business mutation. No token/credential in query/URL.

## Key ownership and configuration

Read existing private prepared `turn-shared-secret` once during API module initialization outside transactions, only when issuer explicitly enabled. No inline secret env support or new key generation, no actual backend .env edits. Fixed-shape bounded regular non-symlink file (64 lowercase hex ASCII plus optional LF); POSIX owner-only/non-root API ownership must match file owner, Windows relies on preparation ACL and later qualification. File errors fail closed with generic safe messages; no private contents/stack/provider errors. Reject equality with configured identity/notification/signal keys. Raw ASCII is the HMAC key; never hex-decode it. Hold only in the API infrastructure adapter's private memory; worker/default-off adapter never reads it. Fail startup on missing/invalid enabled file rather than fake credentials. Secret rotation requires stop/reconcile/synchronized relay/API restart; old bearer allocations are not globally revoked by replacing a file.

Base local Compose remains unchanged to avoid optional secret input breaking ordinary startup. Add a separate API-only local credential override mounting just the existing prepared key read-only, never the full relay config and never worker. Explicit operator opt-in after identified migrations/environment qualification; do not execute it here. Docker file-secret UID/GID bind behavior still applies. No package/image dependency change.
